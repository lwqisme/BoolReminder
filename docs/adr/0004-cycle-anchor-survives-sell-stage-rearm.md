# 卖出阶梯的周期锚点不随卖档重启重置

price_rise_grid 和 cost_deleverage 的卖出触发以周期锚点（首次取平均成本，整轮卖完后上移到现价）为基准。卖档重启只清空阶段标记，**不重置锚点**。此前 JS worker 在重启时把锚点清空回平均成本，长历史持仓的摊薄成本远低于现价，导致深跌买入当天即按买入价卖出（买→重启→秒卖循环）；Python 的 cost_deleverage 则始终按平均成本算盈利，下跌中同样会卖——这是策略语义缺陷而非实现分歧。2026-06 决定：两端统一为"锚点跨重启保留"，`sell_min_profit_pct` 仍按平均成本作为独立的不亏本闸门。

## Considered Options

- **重置为 max(平均成本, 现价) / 现价**：重启后从重启点重新起网格，回收资金快但反弹早期就减仓；被否。
- **锚点随成本下调 min(锚点, 成本)**：深熊中更活跃，但"买入日卖出"会温和地回归；被否。

## Consequences

- 锚点被整轮卖出抬高后（如 480），崩盘再建仓也要等价格回到锚点+阈值（≈518）才恢复卖出——深熊中两个策略会长期静默，这是接受的代价。
- 所有含这两个策略的历史回测、GA 评分、robust 预设结果会变化（卖出次数减少）；不提供旧行为开关。
- "成本去杠杆"中的"成本"不再是字面含义：阶段阈值按锚点，仅 min_profit 按成本。
