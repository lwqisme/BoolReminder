# 统一 LEAPS 卖出信号引擎

LEAPS 卖出逻辑存在两套独立实现：GA 进化的 `compute_sell_ladder`（逐日遍历、追踪档位去重和剩余仓位）和信号生成的 `detect_sell_signals`（只看当日、无档位去重、无剩余仓位追踪）。这导致 GA 验证过的最优参数在实际信号中可能产生不一致的卖出建议。

**决策**：以 GA 引擎 `compute_sell_ladder` 为唯一真源，重构 `detect_sell_signals` 为逐日模拟 + 真实交易覆盖模式。当用户部分执行了某档建议时（如 S1 推荐卖 31% 只卖了 15%），引擎追踪各档累积已卖量，未达标则继续推同档剩余额度。

### 取舍

- **选 GA 为真源**：GA 已在回测中逐日验证，逻辑更完备。代价是信号引擎需要完整价格序列，增加了 IO
- **选方案 B（累积追踪）**：相比"卖过就算过"（方案 A），能处理用户不严格遵循信号的情况。代价是实现复杂度更高
- **不选"不改信号引擎"**：两套逻辑长期不一致会累积偏差，GA 最优参数在实际使用中可能不是最优

### 考虑的替代方案

- **方案 A（宽松兜底）**：S1 有任意卖单记录就推进到 S2。简单但可能严重偏离仓位节奏
- **方案 C（纯真实持仓驱动）**：不追踪档位，只靠持仓量判断。简单但无法区分"S1 没执行"和"S1 执行了但回调后 S1 条件再次满足"
